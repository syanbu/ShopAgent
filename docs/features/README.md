# 功能文档约定

每个功能由一份 Markdown 文档持续记录。文档描述当前有效的设计，并保留影响行为、接口或技术选择的关键变更。

## 何时创建功能文档

以下改动需要创建功能文档：

- 新增用户可感知的能力。
- 新增 Agent 工作流分支或工具。
- 新增或修改对外 API。
- 新增或修改核心数据结构、持久化方式。
- 引入会影响部署或运行方式的外部依赖。

小型修复、内部重构、文案调整和单纯补充测试不单独建文档。如果这些改动改变了外部行为或原有设计，应更新所属功能文档。

## 命名与索引

- 文件放在 `docs/features/` 下，使用稳定、可读的英文短横线名称，例如 `rag-retrieval.md`。
- 一个功能只保留一份主文档，后续修改持续更新该文件。
- 创建或删除功能文档时，同步更新 `docs/README.md` 中的功能索引。
- 索引中的代码入口指向主要模块，不罗列所有相关文件。

## 内容要求

功能文档应说明目标和边界、外部行为、接口与数据、关键决策、代码入口、验证方式及重要变更。设计发生变化时，正文更新为当前状态，变更记录说明变化原因。

功能文档不记录每日进度，不复制提交日志，也不保留已经失效且没有决策价值的实现细节。
