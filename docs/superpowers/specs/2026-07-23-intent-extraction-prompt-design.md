# 单轮意图抽取提示词改进设计

## 目标

修复单轮商品搜索中明确约束被遗漏的问题。用户输入“推荐一款 8000 元以下的手机”
时，`ParsedIntent.constraints.max_price` 应为 `8000`，价格条件不能只留在
`retrieval_query` 中。

本次修改继续由 Qwen 负责自然语言语义理解，不增加正则表达式、关键词表或其他
基于句式枚举的价格解析逻辑。

## 当前问题

当前意图提示词只要求模型返回 `ParsedIntent schema_version 1`，并将价格、品牌和
属性放入 `constraints`。提示词没有提供完整 JSON Schema、字段语义、约束完整性要求
或参考示例。

JSON Mode 只能约束输出为合法 JSON，不能保证模型把用户表达的每项条件映射到正确
字段。模型返回 `max_price: null` 时，结果仍符合当前 Pydantic 类型定义，因此不会
触发已有的格式纠错重试。下游随后按无预算条件执行检索和 SKU 筛选。

## 范围

本次修改包括：

- 为 `ParsedIntent` 和 `SearchConstraints` 的字段补充面向模型的语义描述。
- 将 Pydantic 生成的完整 JSON Schema 注入意图识别系统提示词。
- 在提示词中说明各字段的映射规则、完整性要求和输出前检查要求。
- 增加少量代表性示例，说明价格上下限、品牌和排除条件如何进入结构化字段。
- 增加一个确定性的提示词契约测试，不用 mock 断言概率模型的自然语言理解结果。
- 更新单轮文本商品推荐功能文档，记录意图抽取契约。
- 运行现有测试，并通过真实模型请求检查意图日志和商品事件。

本次修改不包括：

- 不使用正则表达式、关键词表或代码侧价格覆盖逻辑。
- 不增加第二个意图校验模型调用。
- 不修改 `ParsedIntent` 的字段名称、字段类型或 `schema_version`。
- 不修改 SSE 事件顺序、商品筛选逻辑、多轮状态或会话存储。

## 设计

### JSON Schema 来自 Pydantic 模型

`DashScopeIntentParser` 使用 `ParsedIntent.model_json_schema()` 生成输出结构，并以
中文 JSON 写入系统提示词。提示词不再依靠一句“matching ParsedIntent”让模型猜测
字段结构。

`SearchConstraints` 和 `ParsedIntent` 的字段使用 `Field(description=...)` 补充语义：

- `min_price` 是用户可接受的最低 SKU 价格。
- `max_price` 是用户可接受的最高 SKU 价格。
- `include_brands` 是明确要求包含的品牌。
- `exclude_brands` 是明确排除的品牌。
- `required_features` 是商品必须具备的语义属性。
- `excluded_features` 是商品不得具备的语义属性。
- `retrieval_query` 只保留适合向量检索的商品、场景和正向需求，不重复价格、品牌或
  排除条件。

字段描述只影响生成给模型看的 Schema，不改变运行时数据结构和 API。

### 提示词按语义定义字段

系统提示词使用中文，与当前主要用户输入保持一致。提示词要求模型理解语义等价表达，
不按固定词语匹配，也不把示例当成完整句式列表。

价格规则按字段含义说明：

- 用户表达最高可接受价格时，写入 `max_price`。
- 用户表达最低可接受价格时，写入 `min_price`。
- 用户表达价格区间时，同时写入上下限。
- 用户没有表达对应价格边界时，字段才允许为 `null`。

提示词同时要求：

- 用户明确表达的价格、品牌、必需属性和排除属性必须全部进入 `constraints`。
- 不得根据常识补充用户没有表达的约束。
- `product_search` 必须生成非空 `retrieval_query`。
- 类目和子类目只能使用提示词附带的商品目录值。
- 输出前在模型内部检查原始输入中的每项明确约束是否已经映射。
- 最终只输出一个 JSON 对象，不输出检查过程或解释文字。

### 示例用于说明映射，不枚举语言

提示词包含三个代表性示例：

1. “推荐一款 8000 元以下的手机”，`max_price` 为 `8000`。
2. “想买 6000 到 8000 元的手机”，同时设置 `min_price` 和 `max_price`。
3. 带品牌要求和排除属性的商品搜索，分别写入品牌与语义约束字段。

示例后明确写明，同义表达应按相同字段语义处理，示例不是可识别句式的完整列表。

### 保留现有校验和重试边界

模型输出继续经过 `ParsedIntent.model_validate_json`。JSON 无法解析、字段类型错误或
违反现有路由约束时，沿用当前的一次纠错重试；第二次仍不合法时返回
`INTENT_PARSE_FAILED`。

本次不增加代码侧语义检测。模型生成了格式合法但语义遗漏的 JSON 时，Pydantic 仍然
无法判断遗漏。修改通过更完整的提示词降低这种情况，不宣称能让概率模型达到形式化的
百分之百正确。

## 数据流

```text
用户原文
  -> 带字段语义、JSON Schema、类目目录和示例的系统提示词
  -> Qwen3.7-Max 生成 ParsedIntent JSON
  -> Pydantic 校验格式与路由约束
  -> 现有类目纠偏
  -> 记录 parsed_intent 日志
  -> 使用 constraints 执行检索和 SKU 筛选
```

## 验证

在模型网关测试中固定提示词契约：生成结果必须包含 Pydantic 字段描述、价格完整性
规则、代表性示例和紧凑 taxonomy JSON。修改完成后运行与模型网关、查询模型、检索
过滤和工作流相关的测试。

真实模型验收至少检查以下输入：

- “推荐一款 8000 元以下的手机”
- “预算不要超过 8000 元，推荐手机”
- “至少 6000 元的手机”
- “想买 6000 到 8000 元的手机”

第一条输入必须满足：

- 日志中的 `max_price` 为 `8000`。
- `retrieval_query` 不再承担预算约束。
- 8999 元起的 iPhone 不产生商品事件。
- 小米 17 Ultra 只返回 8000 元以内的 SKU。

其他输入用于检查模型能否按字段语义处理不同措辞，不要求为这些输入新增自动化测试。

## 风险

提示词改进依赖模型遵循字段语义，无法彻底消除格式合法但语义遗漏的结果。若真实验收
仍出现稳定遗漏，应单独设计模型评测集或第二次语义校验调用，不能重新引入不断扩张的
正则表达式作为自然语言解析器。

现有 `min_price` 和 `max_price` 只表示包含边界的价格区间。本次不增加排除边界字段，
因此不解决“严格高于”或“严格低于”在数值恰好等于边界时的差异。
