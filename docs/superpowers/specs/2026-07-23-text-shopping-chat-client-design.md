# 文本购物对话测试客户端设计

## 目标

新增一个可直接运行的交互式 Python 客户端，用真实 HTTP/SSE 请求模拟用户连续输入，并直观展示文本购物工作流返回的商品卡片、文本增量、错误和结束状态。

## 范围

- 客户端实现位于 `scripts/chat_client.py`，不修改服务端接口或对话状态模型。
- 默认请求 `http://127.0.0.1:8000/api/v1/chat/stream`。
- 在一次客户端会话中复用同一个 `conversation_id`；该标识只用于链路关联，不承诺服务端保存历史上下文。
- 支持交互模式和通过 `--message` 发起单次请求。
- 不读取或打印 `.env` 中的 API Key。

## 命令行接口

- `--base-url`：服务根地址，默认 `http://127.0.0.1:8000`。
- `--conversation-id`：可选；未提供时生成 UUID。
- `--message`：可选；提供时发送一次后退出，否则进入交互循环。
- 交互模式使用 `/quit` 或 `/exit` 退出，也支持 EOF 和 Ctrl-C。

## 数据流与输出

每条非空消息以 JSON `POST` 到流式聊天端点。客户端按 SSE 事件块解析 `event` 和 `data`：

- `message_start`：显示会话和消息标识。
- `product`：按事件顺序显示商品名称、品牌、价格及可用链接信息。
- `text_delta`：边接收边输出助手文本。
- `error`：向标准错误输出结构化错误信息。
- `message_end`：结束当前响应并显示最终状态。

未知事件会以简洁诊断信息显示，便于服务端协议演进时排查，而不会中断后续交互。

## 错误处理

连接失败、非成功 HTTP 状态、无效 JSON 和不完整 SSE 块均转换为可读错误。交互模式下单次请求失败后仍允许继续输入；单次模式以非零状态码退出。

## 验证

- 用确定性的模拟 SSE 数据验证事件解析和输出格式。
- 运行脚本的 `--help` 验证命令行入口。
- 在本地服务运行时发送购物与非购物消息，确认商品事件、文本流和结束状态均能显示。
