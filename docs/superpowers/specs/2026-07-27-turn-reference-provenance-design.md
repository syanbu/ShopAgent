# 本轮商品引用来源校验设计

## 背景

多轮解析器同时接收当前用户消息、最近候选和焦点商品。模型可能把上下文中的焦点商品
标题补写为本轮 `ProductReference`，即使用户本轮并未说出该标题。例如焦点已经是
`p_digital_009` 时，用户问“有哪些存储版本？”，模型却返回
`surface_text="小米 17 Max"`。工作流把这个非空引用当作显式引用，跳过焦点回退；
简称又无法精确匹配完整标题，最终产生不必要的澄清。

## 目标

- `ProductReference.surface_text` 必须是当前用户消息中实际出现的连续原文片段。
- 当前消息没有显式商品引用时，模型必须返回 `reference=null`。
- 引用缺少原文依据时走现有结构化输出纠错，不能静默覆盖、删除或解析该引用。
- 纠正为 `reference=null` 后，继续复用工作流现有的焦点、单候选和多候选规则。

## 非目标

- 不改变商品名的精确匹配规则。
- 不让焦点无条件覆盖用户本轮明确给出的序数、品牌、商品名或指示引用。
- 不修改会话数据结构、API、SQLite schema 或 Qdrant 行为。
- 不处理品牌对象与商品对象的目标类型问题；该问题单独修复。

## 方案

在 `DashScopeTurnQueryParser` 边界同时做提示词约束和确定性校验：

1. 系统提示词明确要求 `surface_text` 逐字来自当前 `message`，上下文中的候选标题、
   品牌和焦点 ID 只能辅助理解，不能转写为本轮引用。
2. 增加无显式引用的商品追问示例，输出 `reference=null`。
3. `_validate_turn_query` 接收当前 `message`。若 `reference` 非空，则去除
   `surface_text` 首尾空白，并要求剩余文本是 `message` 的连续子串。
4. 校验失败抛出 `ValueError`，复用 `_structured_call` 已有的一次模型纠错。若第二次
   仍不合法，继续返回现有可重试的 `TURN_QUERY_PARSE_FAILED`。

不采用“校验失败后静默把引用改成 null”，因为用户可能确实说了“第一款”，只是模型
错误地把它规范化成候选标题；静默删除会错误回退到旧焦点并回答另一款商品。

## 验证

- 模型首次从焦点虚构 `product_name`、第二次纠正为 `reference=null`：解析成功并发生
  一次纠错。
- 两次都返回不在消息中的引用：安全失败为 `TURN_QUERY_PARSE_FAILED`。
- 合法显式引用仍正常通过。
- 已聚焦商品后的无引用结构化追问继续使用焦点并读取对应 SKU。
