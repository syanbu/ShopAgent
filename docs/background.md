# 基于 RAG 的多模态电商智能导购 AI Agent

> 功能索引与文档约定见 [项目文档索引](README.md)。

## 项目背景

短视频、直播和内容社区已经成为电商消费的重要入口，但传统电商广告仍以图文、短视频等单向展示形式为主。用户看到商品后，即使产生兴趣，也很难围绕预算、使用场景、个人偏好和排除条件继续提问。商品信息与用户需求之间存在断层，导购内容难以直接支持购买决策。

大语言模型、检索增强生成（RAG）和多模态模型为电商导购提供了新的交互方式。用户可以通过自然语言描述模糊需求，也可以补充预算、品牌、成分、颜色等条件，或者上传图片寻找相似商品。Agent 根据商品库中的真实数据完成检索、比较和推荐，让商品浏览从单向展示变成连续对话。

本项目面向电商导购场景，建设一个基于 RAG 的多模态 AI Agent。当前阶段只实现 Python 后端及 Agent 工作流编排，不包含 iOS、Android 或其他客户端开发。

## 项目描述

系统以商品数据集为知识来源，为用户提供商品搜索、筛选、推荐、对比和图片找货能力。现有数据集包含 112 条商品数据和对应商品图片，覆盖美妆护肤、数码电子、服饰运动、食品饮料四个类目；其中数码电子包含 14 款智能手机和 10 款真无线耳机。商品信息包括商品名称、品牌、类目、基础价格、SKU、规格、详情描述、官方问答、用户评价和本地图片路径。

系统需要支持以下交互场景：

- 根据模糊需求推荐商品，例如“推荐一款适合油皮的洗面奶”。
- 根据预算、品牌、类目和商品属性筛选候选商品。
- 在多轮对话中继承并更新用户条件，例如补充预算或调整偏好。
- 识别否定和排除条件，例如“不要含酒精的”“除了耐克还有什么”。
- 对两到三款商品进行比较，并结合用户需求给出选择建议。
- 理解用户上传的商品图片，提取可见特征并检索相似商品。
- 在信息不足时主动询问，避免基于不完整条件直接推荐。

商品名称、品牌、价格、SKU 和图片等事实必须来自商品数据集。数据集中没有提供库存、优惠券、购买链接或实时活动信息，系统不得自行补充这些内容。对于成分或属性未明确说明的商品，也不能将“未知”解释为“符合条件”。

后端对外提供流式对话能力，回复内容同时包含自然语言说明和结构化商品信息，方便后续客户端展示商品卡片。系统需要保留会话上下文，并为模型调用失败、检索无结果和图片无法识别等情况提供明确反馈。

## 技术选型

| 模块 | 技术选型 | 用途 |
|---|---|---|
| 开发语言 | Python 3.11 | 后端服务、RAG 和 Agent 编排 |
| 依赖管理 | uv | Python 版本、依赖和虚拟环境管理 |
| 后端框架 | FastAPI | 对话接口、图片输入和流式响应 |
| 流式协议 | SSE | 持续返回生成文本与结构化事件 |
| Agent 编排 | LangGraph | 管理多轮状态、条件分支和模型调用 |
| 模型服务 | 阿里云百炼 DashScope | 统一调用 Qwen 系列云端模型 |
| 意图、证据与回答 | Qwen3.7-Max | 结构化用户意图、映射语义证据并生成最终回复 |
| 文本向量模型 | Qwen3.7-Text-Embedding | 商品文本、FAQ 和评论的语义向量化 |
| 文本重排序模型 | Qwen3-Rerank | 对文本向量召回的候选商品进行语义重排序 |
| 多模态向量模型 | Qwen3-VL-Embedding | 商品图片与用户图片的向量化检索 |
| 图片理解模型 | Qwen3.7-Plus | 提取图片中的商品类别、外观和场景特征 |
| 向量数据库 | Qdrant | 保存文本与图片向量，支持相似度检索和条件过滤 |
| 会话存储 | SQLite | 保存会话状态和多轮上下文 |
| 数据校验 | Pydantic | 校验商品、模型输出和接口数据结构 |
| 测试框架 | pytest | 单元测试与后端集成测试 |
| 代码质量 | Ruff、mypy | 代码检查、格式化和类型检查 |
| 本地服务管理 | Docker Compose | 管理后端依赖与 Qdrant 服务 |

所有 API Key、服务地址、模型名称和运行参数统一写入 `.env` 文件，不在代码或文档中保存密钥。`.env` 必须加入 `.gitignore`，仓库只提供不含真实值的 `.env.example` 作为配置说明。
